# Owner platform signals and channel publication locks

Only YouTube has a prepared live adapter, and it is disabled. TikTok and Instagram have neither live nor simulated publishing adapters; they are future plan destinations only. The shared CAPABILITIES registry is returned by commands and platform status. No new OAuth scope, third-party service or revenue assumption is introduced.

Official YouTube channels documentation was read for this task: https://developers.google.com/youtube/v3/docs/channels . `auditDetails` has aggregate good-standing fields, including copyright/community standing, but requires the special `youtubepartner-channel-audit` scope and associated MCN/token-lifecycle restrictions. That is not a complete real-time strike event feed for this application's ordinary upload scope. It is not enabled. Videos documentation https://developers.google.com/youtube/v3/docs/videos supplies upload/processing information, not a reliable substitute for complete channel strike notifications. No claim of full/immediate automatic detection is made.

GET `/platforms` shows detection gaps, event history, verification and current locks. POST `/platforms/events` requires the existing strong owner bearer token and a stable Idempotency-Key. Fields: platform, channel_id, kind, occurred_at with timezone, source, verification and note. Sources are owner_report or mock_platform_signal, never silently verified provider observations. Types: copyright_strike, community_strike, platform_warning, account_restriction and upload_error. Source, event time and local receipt time are preserved. Mock events are explicitly marked in API payloads, audit action suffix and notification details.

All kinds except upload_error conservatively lock the affected platform/channel for further publishing. A reported upload error is NEVER a strike. The lock is checked in workflow publication admission and in the prepared YouTube adapter, not just the dashboard. Legacy unassigned jobs map to local-youtube; command jobs use their explicit local channel mapping. Local aliases are not a live-verified Google channel identity: channel ownership/target confirmation is a remaining production prerequisite.

No tick, retry or timeout automatically unlocks a channel. POST `/platforms/review` requires explicit owner_confirmed=true and a review reason; history is retained. A new critical event locks the channel again. Duplicate event keys are idempotent, changed bodies conflict, and alert cooldown is per platform/channel/category. The existing email/WhatsApp mock dispatch is reused. Notification failures never create new strike/job events. No mailbox access, browser scraping, automatic appeals, deletions or contacts occur.

The dashboard distinguishes reported strikes, warnings and failed uploads, shows critical locks and explains the manual-only detection boundary. Even mock critical signals may lock a channel for safety testing; the owner must deliberately review them. Reports distinguish synthetic signals from owner reports and include current blocked channels, while income/ROI remain unknown.
